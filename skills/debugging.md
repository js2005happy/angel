# 系统化调试

修 bug 的硬门：**没有可变红的复现命令，不许动手改代码。**

## 流程

1. **复现**：写一条最小复现命令（测试、脚本或 CLI 调用），先跑一次确认它确实变红。复现不了就先缩小范围，不要直接改。
2. **定位**：用复现命令二分：最近改动、输入边界、环境差异。一次只改一个变量。
3. **修复**：改动要小，只修复现出来的那条路径；顺手重构另开一件事。
4. **回归**：复现命令变绿 + 相关测试全过 + 全量测试无新增失败，才算修完。
5. **记录**：在提交信息里写清复现命令、根因、回归范围。

## 禁止

- 凭印象改代码再“顺便”跑测试碰运气。
- 把失败测试删掉、跳过或改宽松来“修绿”。
- 用探针反复验证已知事实（见 AGENTS.md 写操作安全）。
- 在生产数据、真实用户目录上复现破坏性 bug（用隔离副本）。
