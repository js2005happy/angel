# Nyra · 07 · 代码改名（angel → nyra）

单独一个 PR，A–E 合并以后再做，由 Muse 负责（Milo 定）。

1. 配置目录只加载一个：第一次运行时把 `~/.angel` 迁移到 `~/.nyra`，之后只读 `~/.nyra`，新旧两个目录绝不同时加载。
2. 迁移时，还没用掉的批准状态全部作废，改名后要重新批准。
3. 环境变量：旧的 `ANGEL_*` 在过渡期内照样能用。新旧都设了的时候，以新的 `NYRA_*` 为准，并打印一条警告。
4. `angel` 命令保留为别名，过渡期内现有的脚本和定时任务照常运行。
5. 测试：迁移只执行一次；旧目录里宽松的设置（`full` 模式、受信任的验证命令）不会在迁移后自动生效；批准状态作废后要重新批准；新旧环境变量同时设置时以新的为准。
6. 迁移要做成原子的：先复制到临时目录（`~/.nyra.migrating`），全部完成后再改名成 `~/.nyra`。中途崩溃的话，下次运行删掉临时目录、从头重新迁移，不会出现两个目录同时加载。
7. 权限：`~/.nyra` 是 0700，会话和日志文件是 0600。迁移时不跟随 `~/.angel` 里的符号链接，遇到就跳过并打印警告。
8. 网页端请求头：过渡期内 `X-Angel-Token` 照样能用，同时带了 `X-Nyra-Token` 时以新的为准，规则和环境变量一样。token 本身不变，也不写进 URL。
9. 补充测试：迁移到一半崩溃后能正确恢复；权限是 0700 和 0600；迁移时符号链接被跳过；两个请求头同时带时以新的为准。
