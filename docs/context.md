## `/context` 各列含义

在 REPL 里输入 `/context`，打印当前上下文占用的 breakdown（字符数）：

| 列 | 含义 |
| --- | --- |
| 系统提示 | 系统提示全文（含常驻技能索引描述、AGENTS.md、长期记忆），加上压缩后重读的备注（见下）。 |
| 技能全文 | 本轮全文注入的技能（关键词前 2 + 路径触发命中）的字符数；未命中的技能全文不计入。 |
| 对话历史 | 用户 / 助手消息的字符数。 |
| 工具结果 | role 为 `tool` 的消息的字符数。注意：路径触发的技能是追加在工具结果后面的，算在工具结果里，不算在技能全文里。 |

四列相加等于“总计”字符数。`/context` 无参数时按最近一次 `run` 的任务算技能注入；
刚启动、还没跑过任务时按空任务算（技能全文一般为 0）。

### token 数：实报与估算

- **实报**：模型最近一次响应报告的输入 token（`usage.snapshot()` 的
  `last_prompt_tokens`，与自动压缩 `shouldAutoCompact` 同源）。显示为
  “已用 token：N（模型实报）”。
- **估算**：模型没报告用量时，按 **4 字符 ≈ 1 token** 估算总字符数，显示为
  “已用 token：约 N（估算：4 字符 ≈ 1 token，模型未报告用量）”。
- 估算永远标明“估算”，绝不写成实报。模型窗口（`context_window_tokens`）
  只用用户配置的数字，未配置时显示“未配置”。

## 压缩后重读机制

手动 `/compact` 与自动压缩（auto-compact）成功后，都会自动重读记忆与规则，
保证用户定下的规则不因压缩丢失：

1. 用现有的 `loadMemorySummary(40, memoryPath, home)` 取长期记忆末 40 行；
2. 用现有的 `loadAgentsMd(workdir, home)` 取 AGENTS.md，取其**末尾段落**
   （最后 2 个段落）；
3. 以一条 `[压缩后重读：记忆与规则]` 的 user 备注追加进压缩后的消息列首，
   放在摘要之后、保留消息之前。

失败时不重读：摘要失败走本地回退（fallback），或自动压缩 strict 失败时，
不追加重读备注，避免在已损坏的会话上叠加内容。两边文件都空时也不追加。

重读备注本身计入 `/context` 的**系统提示**部分（按 `[压缩后重读` 开头识别），
不让它成为看不见的隐藏占用。

## `/compact focus` 用法

```
 /compact                  # 原样压缩：摘要 + 保留最近 4 条消息
 /compact focus <关键词>   # 重点压缩：摘要指令追加“重点保留与关键词相关的内容”，
                           # 除最近 4 条外，额外保留含关键词的历史消息
```

- 关键词按空白与 `, ， ; ； 、 | /` 切分，可写多个（如 `/compact focus 部署 回滚`）；
  匹配忽略大小写，中文按子串匹配。
- 额外保留的消息按原顺序、去重（已在最近 4 条里的不再重复），**上限 10 条**，
  避免 focus 把半个会话都留下来。
- `/compact` 不带参数时行为与原来完全一致；focus 为空字符串时等同于不带 focus。

## 优化建议的触发规则

`/context` 末尾的“建议”按占比最高的类别触发：

| 情况 | 建议 |
| --- | --- |
| 总量为 0（空上下文） | 无需优化。 |
| 占比最高的类别 ≤ 50% | 各部分占比均衡，暂无需压缩。 |
| 系统提示 > 50% | 检查 AGENTS.md / 长期记忆是否过长，或精简常驻技能索引。 |
| 技能全文 > 50% | 减少本轮命中的技能，或先 `/compact` 精简会话后再试。 |
| 对话历史 > 50% | 用 `/compact` 压缩会话，或 `/compact focus <关键词>` 只保留重点。 |
| 工具结果 > 50% | 用 `/compact` 压缩会话，旧工具结果会被先折叠。 |

## 网页端

网关的会话视图（`GET /api/sessions/:id`，即 `sessionView`）在原有 `usage`
字段之外新增 `context` 字段，内容与 REPL 的 `/context` 是同一份 breakdown
（`Agent.contextUsage()`）；没有 live agent 的会话（只读会话文件）时为 `null`，
不拼系统提示、不编造数字。

网页端（桌面与手机共用）在会话页的状态行下方有一行上下文占用
（`#context`），随会话轮询刷新，格式如
“上下文：系统 30% · 技能 0% · 历史 50% · 工具结果 20% · 共 1234 字符（123 token，估算）”。
这是挂在现有状态行上的展示，没有为此新建面板。
